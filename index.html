1. Headline Patterns & Strategic Insights

          
Clustered findings across all 100 apps — what the raw table alone hides.

        

      


      

        

          Pattern 01 • The Self-Serve Illusion
          
76% Self-Serve on paper, but 59% true Easy Wins

          
17 apps appear self-serve yet carry real build friction: split auth across endpoints (Help Scout Inbox OAuth2 vs Docs Basic), 3-header custom auth (Copper), multi-DC OAuth routing (Zoho CRM/Cliq), hobby-only non-commercial TOS (Vercel), or paid walls blocking live testing (Front, Pylon, Ahrefs, Smartsheet, Clay, Devin).

        

        

          Pattern 02 • Auth & MCP Parity Gap
          
OAuth2 is standard (80%), yet MCPs break auth parity

          
50% use OAuth2 as primary auth and 80% support it somewhere. Crucially, vendor MCP servers often restrict what REST APIs allow: ClickUp's MCP rejects pk_ tokens (OAuth2 only), Brex's MCP blocks money movement, Plaid's MCP is diagnostics-only, and Squarespace's MCP only covers Domains.

        

        

          Pattern 03 • Category Bifurcation
          
Dev & Productivity (90% Easy Win) vs Finance (20%) & Ads (40%)

          
Developer/Infra and Productivity hit 100% official MCP adoption and 9/10 Easy Wins. Conversely, Finance (2/10) and Marketing/Ads (4/10) are choked by Google/Meta/LinkedIn/Intuit/Plaid compliance & app review gates plus enterprise contracts (PitchBook, DealCloud, Gladly, Otter).

        

        

          Pattern 04 • Where Composio Wins Now
          
79% Official MCP means Composio's moat is orchestration + the 21% gap

          
Commodity single-app CRUD wrappers are rapidly shipping from vendors (62 Remote + 17 Local MCPs). Composio adds immediate leverage via: (a) unified multi-tenant OAuth + write-safety guardrails, and (b) filling the 21% no-MCP/community gap (SendGrid actions, Discord, Telegram, Threads, Pinterest, Copper, Podio, Aircall, Amazon SP-API, Waterfall.io).

          Wave 1 • 59 Apps
          
Ship Immediately (Self-Serve Easy Wins)

          
Standard OAuth2 or Bearer/Basic auth with free sandboxes/tiers (Dev Infra 9, Productivity 9, Support 7, CRM 6, Messaging 6, AI 6, Ecommerce 5, Data/SEO 5, Marketing 4, Finance 2). Ideal for automated OpenAPI → Composio toolkit generation.

        

        

          Wave 2 • 22 Apps
          
Build with Targeted Engineering Scaffolds

          
Buildable without partner deals, but need specialized auth/adapter handling: HMAC/Ed25519 signing (Binance), multi-DC routing (Zoho, Pylon, Lark), triple headers (Copper), split auth (Help Scout), or paid test accounts (SE Ranking, Ahrefs, Smartsheet, Devin, Clay).

        

        

          Wave 3 • 17 Apps
          
Compliance Review & Partner Outreach Queue

          
Split into App Review Gates (Google Ads, Meta Ads, LinkedIn Ads, WhatsApp, Amazon SP-API, Plaid, QuickBooks) and Partner/Sales Gates (DealCloud, Gladly, Aircall, SFCC, fanbasis, Waterfall.io, PitchBook, NotebookLM Enterprise, Otter Enterprise, Paygent Connect).

        

        

          Wave 4 • 2 Apps
          
Local CLI / Workbench Skills

          
Sherlock (Python OSINT CLI) and Mermaid CLI (mmdc Puppeteer binary) have no hosted SaaS APIs. Ship as sandboxed Composio Workbench skills or local stdio MCPs rather than REST connectors.

3. The Research Agent, Composio SDK Architecture & Where a Human Was Needed

          
Built on @composio/core@0.31.0 Tool Router MCP + 3-pass verification loop.

        

      


      

        

          
Pass 1 • Agent Synthesis

          
Composio SDK + Structured LLM Pass

          
Initializes composio.sessions.create(userId, { mcp: true }) and probes composio.toolkits.get(slug), then extracts structured auth, gating, API, and MCP hypotheses into Zod-validated JSON. Result: 75/100 exact.

        

        

          
Pass 2 • Docs & MCP Grounding

          
Targeted Multi-Query Docs Verification

          
Re-queries narrow 2-app & site-scoped doc searches specifically targeting MCP endpoints, deprecated auth methods, and production review walls. Caught 25 semantic misses → 95/100.

        

        

          
Pass 3 • Live Probe + Human

          
100-URL HTTP Probe + 25-App Audit

          
verify_urls.ts fetches all 100 evidence URLs live (fixing 4 stale 404 paths), followed by human cross-check of 25 stratified high-risk/control apps. Result: 99/100 verified + 1 flagged ambiguous.

        

        

          
Output • Dual-Consumer Build

          
Deterministic Pattern Engine + HTML

          
compute_patterns.ts & build_html.ts recompute all cluster stats from raw JSON and emit this zero-dependency HTML + embedded application/json payload.

        

      


      

        

          
Where a Human Was Needed (7 of 25 Audited Cases)

          
Automated search + HTTP probing handles 90%+ of standard SaaS docs, but humans were essential in four failure modes:

          
    
            
  • Brand Collisions & Missing Docs (Paygent Connect, Waterfall.io): "Paygent" collided across Paygent Japan (NTT DATA), withpaygent.com (AI LLM billing), and gopaygent.com/NMI white-label ISOs. Human review flagged Paygent Connect as Low Confidence / Ambiguous rather than hallucinating a wrong product.
    • 
            
  • Sandbox vs. Production Reality (WhatsApp Business, DealCloud): Open developer docs or free test apps fooled Pass 1 into labeling them self-serve; humans caught that live customer access triggers Meta Business Verification or 403 tenant provisioning.
    • 
            
  • Login/Password Walls (fanbasis): Search snippets mentioned payment SDKs, but human inspection confirmed dev-docs.fanbasis.com is password-protected behind rep approval.
    • 
            
  • Non-SaaS & Product Boundaries (NotebookLM, Sherlock): Separating consumer NotebookLM (no official API; browser-cookie hacks) from GCP NotebookLM Enterprise, and classifying CLI tools outside REST buildability.
    •
